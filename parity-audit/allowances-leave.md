## Differences in validation, defaults, enums, calculations

**Enums** — identical on both sides (unchanged backend): allowance `frequency` `MONTHLY|YEARLY|ONE_TIME`; leave `accrualMethod` `FIXED_ANNUAL|ACCRUAL_PER_MONTH|NONE`; `status` `ACTIVE|INACTIVE`; application `status` `PENDING|APPROVED|REJECTED|CANCELLED`. New UI does not offer the CANCELLED transition (see M7) and shows the Accrue action for `NONE` (M19).

**Defaults** — Create defaults still resolved server-side, so bare creates match: allowance `frequency=MONTHLY`; leave type `accrualMethod=FIXED_ANNUAL`, `carryForward=true`, `encashable=false`, `paidPercent=100`, `requiresApproval=true` (`leave.js:56-70`). BUT the new leave-type form exposes only Code/Name/Accrual/Annual days, so Max accumulation, Paid %, Carry forward, Encashable, Requires approval and Remarks can never be supplied by an operator (L9–L14) and, with no edit (L16), can never be changed afterward. OLD's file-leave form defaulted From/To to today; new leaves them blank (M3).

**Client validation** — OLD put `min`/`max`/`step` on month, year, amount and leave annual-days/max/paid% (`views-allowances.js:42-44`; `views-leave.js:42-44`) and required a leave type selection (`views-master.js:1340`). New inputs drop these attributes (`AllowancesPage.jsx:96,100,102`; `LeavePage.jsx:201`); the shared backend still enforces them, so the effect is later error surfacing rather than data corruption.

**Accrual / balance calculations** — unchanged; both UIs call the same service. Key rules preserved: `closing = opening + accrued − availed` (`leave.js:98-100`); accrual is per-month for `ACCRUAL_PER_MONTH` (annualDays/12) and once-per-year for `FIXED_ANNUAL`, guarded by `lastAccrualMonth` (`leave.js:119-127`); `maxAccumulation` caps opening+accrued (`leave.js:128-132`); file-leave checks `closing − pendingSameType` (`leave.js:159-163`); approval re-checks balance and adds to `availed` (`leave.js:182-187`); cancel of an approved application subtracts days (floored at 0) (`leave.js:211-218`). Because the new UI cannot cancel (M7), it cannot exercise the rollback path; because it cannot set Paid %, `paidPercent` is effectively pinned at 100 (L10). Allowance applicability in payroll is unchanged (`applies` by frequency/month/year and post mapping, `allowances.js:68-85`) — but the new UI can never populate the post mapping (A16), so all new allowances apply bank-wide.

## Monetary values / `$` check
No monetary value is rendered without ₹ and no literal `$` currency symbol exists in `frontend/src`. The only currency renderings relevant here are allowance Amount (`fmt.money` → ₹, `AllowancesPage.jsx:42`) and pay figures on the employee pages (₹). `Number(...)` leave-day columns (Opening/Accrued/Availed/Closing, Days) are day counts, not money, so their lack of ₹ is correct.

## Missing actions / filters / confirmations (summary)
- Missing actions: Edit allowance (A13), allowance Posts mapping (A16), Edit leave type (L16), Cancel leave application (M7).
- Missing filters: leave-type picker not filtered to ACTIVE (M3); no balances year filter (M11); no employee search/paging (X3).
- Missing confirmations/prompts: Reject reason prompt (M6); Cancel-application confirm (M7, action itself gone). (Approve had no confirm in OLD either.)
- Missing fields: leave-type Max accumulation, Paid %, Carry forward, Encashable, Requires approval, Remarks (L9–L14); allowance form largely complete.
